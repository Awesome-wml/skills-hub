# 实施台账记录维护指南

> 目标：把“计划文档”和“实施记录”分开维护。
> `docs/dev-plan/` 只负责需求分析、接口口径、方案与任务拆解；
> `docs/ledger/` 只负责记录“做了什么、改了哪里、怎么验证、还有什么风险”。

## 一、什么时候用

- 用户要求补写或新增实施记录。
- 用户要求把某次改动登记到功能台账。
- 发现新增记录仍被写进 `docs/实施台账.md`，需要改写到 `docs/ledger/*.md`。
- 某个功能域还没有台账文件，需要先创建新台账并补到 `docs/ledger/索引.md`。

如果任务只是写方案、排期、字段口径或联调计划，不用本 skill，写到 `docs/dev-plan/` 即可。

## 二、硬规则

1. 禁止继续向 `docs/实施台账.md` 追加详细“实施记录”。
2. 新增记录必须写入 `docs/ledger/*.md` 对应功能台账。
3. 新增记录前，先确认是否已有对应 `docs/dev-plan/*.md`；没有则先补计划文档。
4. 一个任务跨多个功能域时，只在主功能台账写完整记录，其他台账写简短交叉引用。
5. 台账只写结论和影响面，不粘贴长日志、完整 diff、大段截图说明。

## 三、写入流程

### 1. 先判断写到哪里

- 优先复用已有功能台账，先看 `docs/ledger/索引.md`。
- 能明确归属时，直接追加到对应文件，例如：
  - 商品相关：`docs/ledger/商品模块.md`
  - 履约相关：`docs/ledger/履约模块.md`
  - 直播相关：`docs/ledger/直播商品与中控.md`
- 如果没有合适台账，再新建 `docs/ledger/<功能域>.md`，并同步更新 `docs/ledger/索引.md`。

### 2. 再确认计划文档

- 必须检查本次改动是否已有对应 `docs/dev-plan/*.md`。
- 如果已有计划文档，在“关联计划文档”表里登记，并在实施记录里引用。
- 如果没有计划文档，先补计划，再写实施记录。

### 3. 最后追加实施记录

- 统一追加到功能台账的“实施记录”章节末尾。
- 格式优先复用 `docs/ledger/_模板.md`。
- 记录标题使用“日期 + 主题”形式，不再使用 `记录 001`、`记录 143A` 这类易重复编号。

推荐标题格式：

```md
### 2026-06-05 直播排品 SKU 上下架后补调 SKU 详情回查
```

## 四、功能台账标准结构

每个功能台账固定包含以下章节：

1. `## 范围`
2. `## 关联计划文档`
3. `## 批次摘要`
4. `## 实施记录`
5. `## 验证关注点`（可选）
6. `## 遗留风险`（可选）

如果现有文件没有“验证关注点 / 遗留风险”独立章节，可以继续把这两类内容写在每条实施记录里，不必强行重排旧文档。

## 五、单条记录最小字段

每条记录至少包含：

- 关联计划
- 修改文件
- 实际完成
- 验证结果
- 遗留风险

推荐模板：

```md
### 2026-06-05 示例主题

关联计划：

- `docs/dev-plan/2026-06-05-示例计划.md`

修改文件：

- `src/views/example/index.vue`
- `docs/dev-plan/2026-06-05-示例计划.md`
- `docs/ledger/示例模块.md`

实际完成：

- 完成事项 1。
- 完成事项 2。

验证结果：

- 已执行 `pnpm eslint src/views/example/index.vue`
- 人工验证入口：打开 `/example/path`，确认……

遗留风险：

- 风险 1。
```

## 六、索引与主台账怎么处理

### `docs/ledger/索引.md`

遇到以下情况要更新索引：

- 新增了新的功能台账文件。
- 某个功能域说明发生了明显变化，需要同步更新“说明”列。
- 增加了归档目录或写入规则，需要更新索引说明。

### `docs/实施台账.md`

只允许做以下动作：

- 更新拆分规则或迁移说明。
- 增加“当前已拆分入口”这类导航信息。
- 增加指向 `docs/ledger/` 或历史归档的索引。

禁止再把完整实施记录追加回主台账。

## 七、新建功能台账时的命名建议

- 名称要按功能域命名，不按一次性任务命名。
- 优先用“商品模块 / 履约模块 / 直播商品与中控”这种可持续复用的名字。
- 避免使用 `2026-06-05-xxx.md` 作为功能台账名；日期只适合计划文档和历史归档。

## 八、历史归档建议

- 历史超长记录可以按月迁到 `docs/ledger/history/YYYY-MM.md`。
- 主功能台账保留摘要和必要交叉链接。
- 历史归档文件原则上只追加，不反复整理结构，避免制造无意义 diff。

## 九、输出要求

完成记录维护后，至少核对这几件事：

- 本次记录是否写进了正确的 `docs/ledger/*.md`
- `docs/dev-plan/*.md` 是否存在且路径正确
- `docs/ledger/索引.md` 是否需要补入口
- 是否错误改动了 `docs/实施台账.md` 的详细记录区域

如果用户只是让你“补记录”，默认按最小改动处理，不主动大规模搬迁历史内容。
