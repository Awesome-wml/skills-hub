# 从使用职责抽组件

先读当前 `docs/standards/design-system.md` 的职责清单；无仓库时读取包内源快照并标注状态。当前清单中的候选名称不是已存在的代码组件。

1. 实际读取同流程列表、详情及适用子区块，列出单元格、字段行、摘要、区块、标题与操作的职责；记录代码位置和实际界面状态。只看组件目录或设计师的一张列表图不足以判断复用边界。
2. 区分基础控件、语义 atom、业务组合与页面容器。atom 处理一项展示/交互职责；业务组合表达业务对象的信息结构；页面容器负责查询、加载、分区和生命周期。请求、权限、金额计算与状态决策保留在适用调用层，不因抽组件搬进通用展示层。
3. 同一角色在列表/详情分别记录数据输入、Label、空值/长文本、图标、状态、事件和 slot。数据形状不同则保留适配边界，不凭近义字段补值，不为统一外观合并消费者和收货人身份，也不强塞一个有大量 mode 分支的组件。
4. 标明已有独立组件、已有页面片段、待抽取、新增候选与不应合并。已有合适组件直接复用；复用收益不足的单次片段不强制拆分。实际代码提取必须在本轮实现授权内进行；整理目录或 Figma 映射不等于 Vue 已重构。
5. 给稳定角色 ID 绑定 Markdown 条目、Figma 组件/属性、代码组件/消费位置、Token、Icon 和验收。列表导航单号与详情复制编号等行为差异分别保留；例如当前 BizNo 的只读外观不等于禁用复制。

提取成果要有真实角色和使用位置，不能只交 Button/Input 展示板，也不能把整个列表或详情重命名为 atom。业务组件公共 props 与数据字段需读取实际类型/SDK 后决定；已有页面代码仍需核验，不能自动当正确业务规范。

## 跨模块来源

先查项目 `docs/standards/component-catalog.md`，无 checkout 时读 `../assets/component-catalog.md`。BASE 是基础控件，ATOM 是语义展示，PATTERN 是通用组合，BIZ 是业务职责。运行已见、代码已读、Figma 已建、交互已验分别记录；订单样本不代表全库。具体状态、来源和适用差异以目录为准。
