# 同一规范，LFerp 与 Admin 两个目标

用户要求同时输出时两端都纳入本轮，独立报告实际结果。不能只生成原型、计划、manifest 或组件清单就声称 Admin 应用已生成。是否实施到业务仓库依据本次授权；仅整理规范时不顺带重构业务代码。

## 共同输入

读取同一 Markdown 的实际版本/摘要、需求条目、Token、组件角色/属性、Icon 映射、页面状态和动作预期；核验原型及本轮涉及的 Figma 材料。未要求 Figma 时不将其设为前置条件。设计系统规范与业务 Spec 通过稳定 ID 引用。记录共同契约与平台专属差异，不默认相似字段或画面等于相同业务。

## LFerp 适配

本轮 HTML 默认加载 [工程组件运行资源](runtime.md)，与 Admin 复用同一份渲染实现。产品提供页面组合和 mock，开发接真实 SDK/权限；不分别实现两套 Table/Form。只有现有运行资源确实不支持的目标才讨论适配。

发现实际 LFerp checkout 与目标页面，读取仓库团队规则、依赖及页面逻辑，沿用已确认业务逻辑，标记与设计师稿和已有系统视觉规范的差异；未确认内容单列核对，不另写相同业务 Spec。按现有 HTML/CSS/JS 和组件方式生成/更新受影响原型，不另造 CRUD 框架。演示数据、localStorage 和多状态开关明确为原型能力；不模拟成真实接口成功或账务事实。写入前核对 WIP、文件边界和目录权限，写后实际打开相关状态与交互，记录源规范 ID 与摘要。

## Admin 应用适配

在实际拥有代码的子仓库读取 AGENTS/规范、真实组件、类型和 SDK。把同一角色映射为现有 Vue/Element Plus/VabSchemaTable、VabSchemaForm、VabDetailPage 的 props、slot、schema；按实际需要且在授权内提取业务组件。业务请求、权限和状态迁移沿真实链路，不将 LFerp mock 接到生产实现，不猜字段或加兜底。

根据改动执行适用构建/测试、真实 UI 与数据结果检查。接口或后端未就绪时保留已完成的独立部分，明确缺失，不能把骨架、静态截图或成功构建当作应用联调完成。除非明确纳入，Admin 输出不扩展到 octopus-user 或移动 App。

## 两端交接与再生成

为每端记录：源规范定位/摘要、条目和角色 ID、Token/Icon/组件映射、实际文件/节点、采用的接口或演示数据来源、验证结果。公共差异逐项核对；允许的平台差异记录出处。

重复执行先比较源、组件库、接口与目标文件。只更新本轮受影响对象，保留手工改动及未变证据；任一端未生成或未验证都直接标明。设计定稿不会自动合并代码或部署。
