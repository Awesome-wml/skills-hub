# 界面质量

用于 Figma 设计复核与 Web 实现检查。项目规范决定组件、样式及业务目标；通用指南提供可访问性、键盘、表单反馈、内容溢出和性能检查，不自动改写业务要求。

## 获取规则

目标电脑已有 `web-design-guidelines` 时加载其 Skill，并按其要求读取当前规则。没有该 Skill 时，可直接读取同一公开来源，不把全局安装插件作为流程前置条件：

https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md

记录实际读取时间、URL 和内容摘要。无法读取时明确“外部指南未核验”，继续当前项目规范允许的独立工作；不能宣称执行了最新版检查。产品团队固定指南版本时遵守该版本，更新差异另行列出。

## 应用范围

- 设计检查：清晰标签、焦点/禁用/错误等有来源的适用状态、文字与背景对比、长文本/金额列、布局溢出、弹层可关闭、状态不只靠颜色区分。
- 代码检查：语义化按钮/链接、输入标签、键盘和焦点管理、表单错误、减少动态效果、图片尺寸、列表性能与实际路由行为；Figma 截图不能证明这些行为通过。
- Vue/Element Plus 项目只采用框架无关规则或对应的 Vue 写法；不把 Next.js、React hook、英语大小写建议直接写进中文 ERP 规范。性能建议按实际数据量与分页方式判断，不仅因总记录数多就强制虚拟化。

## 结果与冲突

每条问题保留稳定 ID、规则来源、页面状态或文件位置、证据和处置状态。区分“来源已有行为”“项目规则冲突”“通用质量缺陷”“未验证/不适用”。

例如日期切换即筛选、原型行操作数量与项目标准不一致时，指出具体差异；通用检查不自动授权改变查询触发或删减操作。现有主色对比不足时报告对应 Token 和测量值，不私自改全站主色。来源缺失的设计状态不能因为指南提到就变成已确认业务能力。

输出问题清单与未覆盖项。通过的文件检查、Figma 视觉检查、实际浏览器交互和业务 UAT 分别记录；仅结构校验通过不能标为端到端通过。
