# 验收模式

沿同一份交接逐条检查，并按 [界面质量](ui-quality.md) 检查适用的通用 Web 规则：

| 维度 | 证据 |
| --- | --- |
| 业务 | 用户指定的权威来源及其可追溯 Spec；本轮为设计师样稿＋已有系统；字段、动作、状态迁移、权限、校验与结果 |
| 视觉 | 对应 Figma frame/state 与实际页面截图；布局、字号、间距、颜色、圆角、密度、素材位置与比例 |
| 组件 | 实例/variant/slot、代码组件和 Token 的映射；不只看名称相似 |
| 接口结果 | 测试环境、代码版本、稳定记录 ID、请求与目标回读；财务或不可逆动作由用户按授权完成 |
| 一致性 | 同一范围与状态下，权威来源→Markdown 规范→LFerp/设计/实现→验收条目可追溯 |

加载/空/错误/只读等界面状态也要在对应状态观察。检查与已确认需求实际相关的状态和入口，不硬凑统一清单。自动化测试可作为证据的一部分，不替代实际关键路径和产品验收。

记录每条 passed/failed/not-run/blocked；没有真实环境就记录未执行及具体缺口。不要用 mock、漂亮截图、接口 200、PR 合并或服务健康证明业务结果。是否合并、部署、发布和关闭工单分别报告，未获授权不执行。

发现差异定位到来源条目、Spec ID、设计 frame/state、实现文件及证据。不要把缺陷悄悄改成新的预期，也不把验收失败自动改写产品规则。
