# 从当前 Octopus 建立基础库

适用于基于现有产品统一规范、组件和 Token。先基础库，再以真实页面验证；设计师样稿与已有系统是当前规范任务的依据；LFerp 在页面阶段提供已确认业务逻辑，不从其旧样式推导视觉或组件基线。

## 基线证据

1. 定位用户指定或正在使用的 Octopus 环境、页面、主题和布局密度。未指定环境时先从已有入口发现并说明；无法判断时只问影响基线的具体环境，不把 Dev、UAT、生产或本地 WIP 混用。
2. 在实际浏览器只读观察常用组件。记录运行页面 URL、读取时间、部署资源标识及摘要；由可用浏览器工具读取必要的计算样式与 CSS 自定义属性。只读样式和结构，不采集令牌、存储、网络业务数据或真实客户资料；不为检查而切换团队配置、保存个人视图或操作业务记录。
3. 对应实际子仓库的组件源码、类型和规范；记录提交及相关 WIP。不能从本地 HEAD 推断部署版本。比较运行计算值、部署 CSS 和源码默认值：主题覆盖可能改变圆角、字号、主色、密度。区别 Token 的语义、源码默认值、当前主题值以及组件局部覆盖。
4. 仅带入已核验的 Token：颜色、文字层级、间距、圆角及常用控件尺寸。内容撑开的行高是样本测量值，不直接变成所有表格的固定行高；根字号也不能代替控件实际字号。字体先查 Figma 是否可用，缺字体明确阻碍或替代草稿，不能声称视觉完全一致。

有 [运行样本快照](../assets/runtime-baseline.json) 时可用于离线对照。它与 Git 源码基线分开，保留环境、读取日期与部署 CSS 摘要；日期已过或环境/主题改变时重新核验，不将捕获样本视作永久实时值。`getComputedStyle().fontFamily` 只证明 CSS 字体栈，不证明最终字形来自哪个字体。

## 规范执行版（2026-11-09 登记）

Figma 规范执行版「冷丰ERP·UI规范与组件库」`izYwAFHoZnkV6AxgkhYgyC`（封面 v2.2）是视觉规范的唯一设计源，详见 [设计系统源](../assets/design-system-source.md) 的材料与版本表及「规范执行版登记」。其 01 Token 页（`1:86`）为权威 Token 页：六节工程变量映射与冲突裁决声明——与 Octopus 规范冲突一律以该页为准，工程现状色差（如工程主色 #F76B15、文字 #303133 等）按「工程跟进」处理，不反向修改规范；七节给出工程组件映射（StatusTag=el-tag 挂 28 项矩阵、Toast=ElMessage、表单抽屉=VabSchemaFormDrawer 等）。建立基线时先读该库再对运行环境核验：运行值与规范不一致属工程跟进项，记入差异清单而非当作规范依据。库内已知取值疑义（行高 67/64、字号 13/14 档、04 页缺详情页模板等）见登记记录的待确认清单，遇到时向用户确认，不自行择一。

## 设计师修改稿

收到设计师文件后，沿同页相关画面、展开/收起/滚动状态与浮层检查；读取实际变量、文字/效果样式、主组件和实例数量及属性，不只看一张截图。把当前运行基线与修改稿分列，按语义记录 Token、组件、布局和状态的差异及源节点。修改稿里的新增业务字段、状态或按钮只记为材料内容，不能仅据静态画面推断后端能力或已确认需求。

设计师普通 frame 不等于可复用组件；只有检查了 COMPONENT/COMPONENT_SET/INSTANCE 及属性才能报告组件化程度。缺少的组件、样式、变量命名/作用域/代码映射单列为补齐项。看稿与比较不自动授权修改设计师原件或把候选视觉值覆盖当前运行基线。

状态证据区分：实际观察的交互、运行组件 CSS 已解析的状态样式、源码定义、设计师画面以及通用建议。解析到 hover/focus/disabled 颜色不等于键盘/鼠标行为已验收。

## 组件化与交付

- 按当前页面证据整理基础控件、组合组件和页面模板。常用候选包括按钮、输入/下拉、日期区间、状态标签、单号链接、表格/分页、表单及详情容器；实际存在才列为“已有”，不把候选清单当成全部已验证。
- 每个组件绑定代码定位、真实 props/slot、适用 Token 与 Figma 节点。已有组件优先复用，缺失项单列；搜索结果名称相似不代表属于 Octopus。
- Figma 变量注明环境、主题、来源与版本；组件实例绑定变量及属性。先交付有证据的状态，hover/focus/disabled/错误等未观察或未对应源码时标为未验证，不套用通用 UI 库伪造匹配。
- 完成基础库的结构与视觉核验后，才用订单列表等页面验证组合能力和缺口。运行界面存在缺陷时如实记录；“以当前为基准”不等于把缺陷写成规范，也不授权直接修全站。
- Skill 与共享基线携带去标识化的规则和映射；不把用户真实业务记录、页面里的个人资料或连接身份打进安装包。

按 [界面质量](ui-quality.md) 审查适用项。完成状态分别记录运行已观察、Token 已核验、组件已映射、Figma 已生成、视觉已验证、页面模板已验证；缺一项就不能宣称完整设计系统或三方已共识。
