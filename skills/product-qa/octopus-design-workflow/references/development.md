# 开发模式

实现前与界面检查时加载 [界面质量](ui-quality.md)。先遵守 Octopus 的 Vue/Element Plus 组件与 Token 约定；通用指南中的 React/Next.js 示例只在技术栈适用时执行，不为套用示例更换框架或引入依赖。

1. 从同一份交接定位 LFerp 已确认业务材料、已有 Spec、适用规范与设计节点；已有 Spec 直接引用，未要求新增时不重复建立。读取实际内容并查看本轮变更，不能只读取截图或只看 LFerp 入口页。明确选用原生模式时才读 Figma Spec。读取项目 AGENTS/CLAUDE 及适用组件规范，记录代码分支/提交和 WIP。
2. 获取设计上下文与截图，覆盖目标画面及状态。稀疏响应需要继续读取相关子节点；截图是视觉目标，不能当实现资源。读取变量、文字样式、布局约束和组件属性；对照映射按真实 Vue/Element Plus 栈实现。
3. 复用 Code Connect 对应组件或已有合适组件/Token，通过已有 props/slot/schema 表达。只有证实不能表达时才提出最小组件扩展。不要把 Figma 导出的临时 React/绝对定位代码直接当 Octopus 实现。
4. 业务逻辑沿用 LFerp 已确认材料及已有 Spec，直接引用原定位；未确认内容或冲突单列核对；提交字段来自真实 SDK/接口。Mock、localStorage 和原型中的金额不替代接口事实。保留应继续允许的历史、导入、手工及异常入口，按本次实际业务范围覆盖，不做无关全域排查。
5. 先列“应改变/必须保留”，再改动。接口、权限或后端提交未部署时不能用旧公共 Dev 证明新行为。真实 Local B/Dev 验收不使用 VITE_E2E=true 或 mock。
6. 定向验证功能、视觉、状态、素材位置与比例。写实现定位和证据回交接；缺陷指出对应 Spec 条目和 frame/state。若 Spec/设计已变，重新比较相关部分，不继续补丁式追旧版本。

样式同步是从当前 Figma 设计读取组件属性、变量和截图，并按项目 Token 映射实现及比较。不要每次重新截图描摹、把样式值写死、或为了迁就代码默改设计。需要修改产品 Spec/设计时遵守本次用户授权；有冲突先提出具体差异。
