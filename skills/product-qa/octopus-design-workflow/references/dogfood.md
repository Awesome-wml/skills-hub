# 用本 Skill 完成真实任务

以用户正在推进的页面为样本，进入产品、开发或验收模式实际执行。先读取本 Skill 的当前入口和该模式参考，不另写一个绕过本 Skill 的流程。

生成/规范化原型时使用 `references/prototype.md` 的相应入口。生成前测试能否从业务逻辑按组件规范得到实际页面；生成后测试能否从已有原型得到规范化页面、来源对照、前后差异及业务验证证据（仅保留已核验正确的逻辑）。两条入口单独记录结果；其中一条未执行就标为未执行，不能因入口文案齐全而声称两种能力都已验证。

保留一份精简任务账本：

- 当前完成目标、允许写入的对象、材料入口与已读状态、代码/规范版本。
- 已实际调用的能力及结果：连接身份、目标团队、设计节点、正文摘要、组件/Token 映射、界面问题。
- 遇到的 Skill 缺口、造成的实际影响、对应修订，以及修订后重新执行的证据。
- 已执行、失败、受阻和未执行的检查；生成、共享、开发、部署和三方确认分别记状态。

发现指令缺口时先做能复现问题的最小修订，再在同一真实样本上重跑受影响步骤。不要仅靠新增几段说明或通过格式校验就声称 Skill 已实用验证。不要把某个原型的特有业务写成所有项目的强制规则。

本地正文尚未共享或存在未决来源冲突时，保留工作稿和真实阻碍；正式交接校验应失败，不能为了过检查虚填提交、远端链接或已确认状态。按当前阶段交付可审查成果，并明确下一阶段入口。
