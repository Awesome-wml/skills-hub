# 建议语义、命名与标准词汇规范

参考业界成熟的界面文案、句式表达、命名策略与标准词汇实践，在 AI 生成或修改界面文案时，统一进行语义归一和错误表达替换。

## 1. 适用范围

**【强制】** 只要产出中包含面向用户的文字，都必须遵守本规范，包括但不限于：

- 页面标题、分组标题、按钮文案
- 表单标签、占位提示、校验提示
- 弹窗标题、弹窗正文、二次确认文案
- 空状态、结果页、操作反馈、异常提示
- 表格列名、卡片说明、引导说明、操作建议

- 若原始语义存在错别字、别名混用、表达生硬、口语化、时间模糊、术语不准等问题，但业务意图明确，**最终输出必须直接替换为规范表达，不保留错误写法**
- 仅修正文案表达，不得改变业务规则、法务口径、接口字段名和数据库字段含义
- 规范词优先级：**项目术语表 > 行业通用术语 > 通用文案规范**

## 2. 基础原则

**【强制】** AI 在生成建议语义时，必须同时满足以下要求：

- 准确性：避免错别字、错误术语、歧义指代和模糊时间；英文专名、缩写、大小写保持正确
- 一致性：同一页面、同一流程、同一功能内，对同一个事物只使用一个名称；句式、语态、语序、数字格式保持统一
- 易读性：精简句子，删除无信息增量的套话、重复主语和冗余修饰；优先使用用户熟悉的词
- 重要信息前置：先写结果、限制、风险或下一步动作，再补充说明
- 信息完整可执行：尤其是异常提示和操作建议，不能只给结论不给下一步
- 时间、数量、金额、比例、状态必须明确，不得使用“近期”“尽快”“月底前”等模糊表述

## 3. 句式表达

**【强制】**

- 句式优先使用“对象 + 动作 + 结果/状态”或“事实 + 下一步动作”，避免倒装和被动语态
- 优先陈述当前发生了什么，再告诉用户下一步怎么做
- 使用简单句式，减少多层定语、长前置修饰和口语化赘述
- 默认使用第二人称“你”，不使用“您”“亲”等过度客套或口语化称呼
- 表达应平等、谦逊、克制、友好，不责怪用户，不使用极端措辞

示例：

- 推荐：`商品发布成功`
- 不推荐：`成功发布商品`
- 推荐：`上传失败，请检查文件格式后重试`
- 不推荐：`操作错误，无法上传`

## 4. 命名策略

**【强制】**

- 用词专业严谨，优先采用行业通用、用户可理解的名称，不生造概念
- 默认直白描述功能或对象，避免为了“显得高级”而过度包装
- 命名要考虑长期沿用和扩展性，避免随着功能演进迅速过时
- 避免歧义、错误联想、近义混用和负面暗示
- 操作名称、入口名称、页面标题、结果反馈中的对象名称保持一致

## 5. 异常反馈与建议表达

**【强制】** 出现报错、失败、限制、校验、空状态时，默认按以下方式归一：

- 不直接输出“失败”，优先改写为“无法完成某操作”或“暂时无法某操作，请稍后重试”
- 校验提示优先使用“请输入”“请选择”“请上传”“请补充”，而不是“不能为空”“不能不填”
- 空状态优先使用“暂无”，不要使用“没有”“未发现”这类生硬表述
- 不责怪用户，不使用“你输入错了”“请勿”“不要”“不能”等命令式或指责式表达
- 不使用“永远”“绝不”“必须马上”等绝对化语气，除非业务规则或法规明确要求
- 默认使用“你”，不要在同一段中混用“你”“我”“我们”；只有平台/审核方作为动作主体时，才使用“我们”

## 6. 标准词汇使用规则

**【强制】** 当术语表中存在映射时：

- 最终产出只能使用规范词，不得在同一页面、同一说明中混用错误词、别名和规范词
- 若用户输入或历史文案使用了错误词，但意图明确，输出时直接改成规范词
- 若发现新的行业术语、易错字、专业别名，应优先追加到标准词汇表，再在各项目中统一使用
- 若术语尚未登记且无法确认唯一标准，选择更通用、更易理解的表达，并尽快补充到标准词汇表
- 默认按基础标准词汇执行；项目专有词、行业专有词可在后续词表中增补，但不得回退为错误写法

## 7. 标点与格式约束

**【建议】**

- 标题、标签、单行提示、按钮文字通常不加句号
- 多句说明、列表说明、带链接的整句文案应补齐标点
- 谨慎使用感叹号，除欢迎、祝贺等少数场景外默认不用
- 统计、数量、编号优先使用阿拉伯数字
- 中英文混排、数字与中文单位混排时保持清晰可读，例如 `2 个`、`50%`

## 基础标准词汇表

后续新增专业词汇、别名、禁用语时，统一追加到本表，不要散落在规则正文中。

说明：基础规范优先收敛文案，减少同义混用。若个别业务必须保留更细颗粒度的术语区分，再在项目词表中单独追加。

### 名词

| 类别 | 不推荐/错误 | 推荐/规范 | 适用说明 |
| --- | --- | --- | --- |
| 通用词汇 | 其它 | 其他 | 通用中文规范写法 |
| 模板名称 | 模版 | 模板 | 通用规范写法 |
| 用户称谓 | 您 | 你 | 默认产品场景使用“你”；正式公文类除外 |
| 当前对象 | 该订单 / 该页面 / 该记录 | 此订单 / 此页面 / 此记录 | 指代当前对象时，“此”更明确 |
| 账号体系 | 帐号 | 账号 | 登录身份标识统一使用“账号” |
| 资产体系 | 账号 | 账户 | 涉及资金、余额、结算时使用“账户” |
| 状态文案 | 没有数据 / 没有记录 | 暂无数据 / 暂无记录 | 空状态保持中性、稳定 |
| 登录动作 | 登陆 | 登录 | 用户进入系统的动作统一写“登录” |

### 动词与操作

| 类别 | 不推荐/错误 | 推荐/规范 | 适用说明 |
| --- | --- | --- | --- |
| 新建类操作 | 添加 / 新建 | 新增 | 当前基础规范统一使用“新增”；后续如业务必须细分，再单独补充 |
| 完成状态 | 完结 | 完成 | 常规任务、流程、提交结果统一写“完成” |
| 等待提示 | 请稍后 + 无动作 | 请稍候 | 表示短暂等待，后面不接动作 |
| 重试提示 | 请稍候重试 | 请稍后重试 | 表示延后再执行某个动作 |
| 确认类按钮 | 确认 | 确定 | 单独按钮文案默认使用“确定” |
| 确认类动作 | 确定删除 | 确认删除 | 需要带动作对象时使用“确认 + 动作” |
| 去除操作 | 移除 / 删除 | 删除 / 移除 | 永久去除用“删除”，暂时移出当前集合用“移除” |

### 提示与反馈

| 类别 | 不推荐/错误 | 推荐/规范 | 适用说明 |
| --- | --- | --- | --- |
| 校验提示 | 不能为空 / 不能不填 | 请输入… / 请选择… / 请上传… / 请补充… | 直接告诉用户下一步怎么做 |
| 异常反馈 | 保存失败 | 暂时无法保存，请稍后重试 | 只给“失败”不够完整 |
| 异常反馈 | 删除失败 | 暂时无法删除，请稍后重试 | 补充结果和下一步动作 |
| 异常反馈 | 提交失败 | 暂时无法提交，请检查后重试 | 校验类场景可补充排查动作 |
| 用户输入错误 | 抱歉，输入有误 | 请检查后重新输入 | 不责怪用户，也不替用户道歉 |
| 系统责任致歉 | 对不起 | 抱歉 | 仅系统原因导致的问题使用“抱歉” |
| 绝对表述 | 永远 / 绝不 / 一定 | 避免绝对化表述 | 除非规则、协议、法规强约束 |
| 时间表达 | 近期 / 尽快 / 月底前 | 明确日期或时间范围 | 时间必须具体明确 |

## 行业与项目术语表

以下术语用于仓储、电商订单及相关管理场景，并会通过 `make distribute` 同步到多个前端仓库中的 Cursor 规则，用于约束 AI 生成或改写界面文案，避免出现错别字、近义词混用和非标准名词替换。

解释约定：

- 名词类解释统一使用“指……”
- 状态类解释统一使用“表示……”

### WMS 基础信息术语

| 名词 | 解释 |
| --- | --- |
| WMS | 指仓储管理系统，用于管理仓内业务执行。 |
| 基础信息 | 指 WMS 主数据模块，用于维护仓库、货主、储位、容器等低频变更数据。 |
| 仓库 | 指仓储体系最上层实体，其他空间主数据均隶属于该实体。 |
| 仓间 | 指仓库下一级空间单元，常见唯一性约束为“仓库 + 仓间编码”。 |
| 库区 | 指仓间下的功能分区，可配置移入暂存储位和移出暂存储位。 |
| 作业区域 | 指仓库下的作业功能分区，用于作业组织和储位关联。 |
| 储位 | 指最小库存存放单元，用于承载上架、拣货、盘点等作业路径规则。 |
| 货主 | 指库存归属方，通常为客户或品牌方，与商品、库存和权限管理相关。 |
| 商品 | 指商品主档数据，WMS 侧以查询展示为主，通常由上游系统同步。 |
| 容器 | 指承载货物的周转单元，如箱或托，包含状态、类型和管理模式等属性。 |
| 容器型号 | 指容器规格模板，用于定义长、宽、高、承重、体积等参数。 |
| 承运商 | 指运输服务主体；当前需求中由上游系统同步，WMS 侧不维护新增和修改。 |
| 站点 | 指配送或交付节点；当前需求中由上游系统同步，WMS 侧以查询展示为主。 |

| 周转策略 | 指定义库存排序和出入库优先消耗规则的策略。 |
| 权限管理 | 指控制功能可见性和数据可见范围的模块。 |
| 作业档案 | 指某仓库下可用作业规则集合的主档。 |

| 仓配入库 | 指配送链路中的仓配到门店入库场景。 |
| 客退入库 | 指客户退货到门店的入库业务类型。 |

| 质检 | 指对入库商品进行质量状态判定的过程，如合格、不合格、待处理，用于决定商品是否可进入可用库存。 |

| 库存量 | 指当前库存总量。 |
| 占用量 | 指已被业务占用、暂不可用的库存数量。 |
| 可用量 | 指可用于分配或出库的库存数量，等于库存量减占用量。 |

### 订单状态术语

| 状态 | 解释 |
| --- | --- |
| 待付款 | 表示用户已提交订单但尚未完成支付，订单未正式生效，通常仍可支付或取消。 |
| 待发货 | 表示订单已完成支付，正在等待仓库进行拣货、打包和发货。 |
| 待提货 | 表示订单商品已配送至指定自提点或门店，正在等待用户到店核销并提取商品。 |
| 退款中 | 表示用户已发起退款申请，平台、商家或系统正在审核或处理中，退款结果尚未完成。 |
| 已退款 | 表示退款申请已处理完成，退款金额已按原支付路径或指定方式退回。 |
| 退款关闭 | 表示退款流程已终止，通常因退款申请被拒绝、超时关闭、用户撤销申请或订单条件不满足退款要求。 |
| 已取消 | 表示订单在履约完成前已被用户或平台取消，不再继续支付、发货或提货流程。 |
| 已完成 | 表示订单已完成全部履约流程，通常指用户已签收或提货完成，且订单交易正式结束。 |

const submitError = '暂时无法提交，请检查后重试'
