# 产品逻辑生成原型的组件使用规范

沿用 [已确认的四项分工](../../plugins/octopus-design-workflow/skills/octopus-design-workflow/references/composition.md#已确认的分工2026-10-29)：LFerp 承载已确认产品逻辑，已有系统＋设计师稿提供视觉规范，Skill 映射现有 Element／Vab 组件并生成规范原型，Figma 展示规范与本轮变化。读取和引用已有页面、流程、字段、交互，不重复写业务 Spec。Markdown 维护组件指导与差异；未确认内容或来源冲突单列核对。本地文件尚未发布为团队共享版本。

## 1. 产品描述先落到界面契约

本规范有两个调用入口：**生成前约束**（业务逻辑 → 按 Token/组件/模板生成原型），以及**生成后规范化**（已有原型 → 对照权威来源确定应纠正/应保留 → 按同一规范调整界面）。可在产品工作任意阶段调用同一个 Skill。已有原型做展示规范化时，不要求重写完整业务 Spec，也不以 Figma 接入或整套组件库完成作为前置条件；实际检查与变化仍需可追溯。

每个页面使用已有页面 ID，每个字段、表格列、动作和状态保留稳定 ID。自然语言说明须能回答下表的适用项；无来源的业务含义保持待定，不由组件模板补出。

| 对象 | 产品逻辑需要明确 | 原型生成需要明确 |
| --- | --- | --- |
| 查询字段 | 含义、匹配方式、选项、默认值、触发和重置 | 标签、控件、默认/展开位置、依赖字段、空值 |
| 表格列 | 内容、单位、展示字段、关联对象、空值 | 组件职责、对齐、溢出、显隐、固定、点击结果 |
| 操作 | 出现条件、可用条件、作用对象、确认及结果 | 按钮层级、直出/更多、弹窗/抽屉/跳转、处理中和失败 |
| 详情区块 | 与列表同一对象、内容、关联和动作 | 容器、摘要/明细、加载/空/失败、返回路径 |
| 状态 | 已有状态及允许的动作、变化后的结果 | 文案、标签级别、颜色语义；展示组件不推导状态机 |

尚未对接接口时记录“产品逻辑名 / 原型绑定”；开发时再核验真实 SDK 字段。不能把 HTML 属性名当作接口字段。

## 2. 按职责选现有组件

| 逻辑意图 | 生成原型的表现与边界 | Admin 对应 |
| --- | --- | --- |
| 输入关键词 | 输入框；说明包含/精确等真实匹配规则；切换维度是否清空取自页面逻辑 | Schema 查询字段 / Element Plus 输入 |
| 固定选项 / 多选 | 选择器 / 多选器，展示 Label，编辑和查询保留 value | Schema 字段；Label 不充当提交值 |
| 时间范围 | 范围控件及已有快捷项，明确即时执行或点击查询 | 项目时间范围字段；不得改变业务触发 |
| 勾选行 / 选项 | 选择框的未选、选中、半选、禁用和键盘焦点；选择范围与行为保持原契约 | `VabSchemaTable` selection / Element Plus Checkbox |
| 点单号查看详情 | 可划选的导航单号；选择文字不跳转 | ATOM-001 / `DocNoLink` |
| 复制非导航编号、明文电话 | 当前值局部悬停与复制反馈；掩码和空值不复制 | ATOM-002 / `BizNo` |
| 时间值 | 统一日期/时间模式；不改变时区和精度 | ATOM-003 / `VabDateTime` |
| 金额 / 数量 | 右对齐，保留单位与原空值；不自动计算合计或填零 | ATOM-004 / 已有 formatter 与 `is-money` |
| 状态 / 分类 | 核心状态为 L1；描述分类 L2；辅助 L3；一行最多一个 L1 | ATOM-005 / 现有 Tag / Label |
| 商品信息 | 图文、规格和已有明细入口；列表摘要与详情明细分别适配 | BIZ-001 / 当前商品单元格，公共组件待提取 |
| 买家 / 收货信息 | 买家与收货人分清；组合显示不合并身份或猜字段 | BIZ-002、003 / 现有片段，公共组件待提取 |
| 金额明细 / 物流 / 进度 | 只展示传入的已确定内容；请求、权限、账务在调用层 | BIZ-004、005、006 / 现有详情片段 |
| 列表 | 查询、业务工具栏、结果、分页；视图设置和导出在辅助区 | PATTERN-001 / `VabSchemaTable` |
| 新增 / 编辑 / 只读详情 | 按行为选表单、详情容器；有编辑逻辑才使用编辑表单 | `VabSchemaFormDialog/Drawer`、`VabDetailPage` |

候选业务组件是现有片段的复用职责，不代表已新增 Vue API。职责、源码与 Icon 定位见 [设计系统目录](design-system.md)。

## 3. 原型必须遵守的现行表现

- Token：颜色、字、间距、圆角引用 [design-tokens.md](design-tokens.md)；运行快照只提供本轮主题/密度的取值，不覆盖主题源码。LFerp 适配层映射到相同语义，禁止每页另造一套色板。
- 密度：按钮、输入、选择器与分页使用同一密度；表格行高由内容和密度决定，不把一条样本行高设成全局固定值。
- 查询：默认展示现行规范要求的高频项数量，其余展开；查询/重置在末位。查询触发沿用 LFerp 已确认的业务材料；未确认或冲突的触发方式单列核对，不能由样式规范擅自改变。
- 工具栏：业务动作和视图辅助分区；危险动作不设为主按钮。已有多个导出不能因设计稿只有一个按钮就删除。
- 列：金额/数量右对齐；商品、地址等长文本显式左对齐；普通列默认居中。列宽根据内容与密度；显示省略时仍能读到完整内容。
- 操作：按现行规范直出不超过两个，其他进“更多”；按权威系统核验出现条件和处理器，正确部分才复用。改变操作集合或可用条件是业务变更，不能由样式规范决定。
- 反馈：空查询显示“未查询到符合条件的数据”；原型未具备真实请求、错误或权限链路时明确缺口，不能以演示成功充当联调验收。
- Icon：查询、重置、展开、复制、导出使用已有真实资产；装饰图标不替代按钮文字。现有 LFerp 图形尚未逐个匹配 Admin 时标记待对齐，不能用相似字符宣称完成。

来源：[list-page.md](list-page.md)、[table.md](table.md)、[data-format.md](data-format.md)、[status-dictionary.md](status-dictionary.md)。

### 现有组件直接运行

HTML 原型使用 [工程组件运行入口](../../prototype-runtime/README.md)，加载由现有 Vue / Element Plus / Vab 源码构建的资源。页面本身承担组装、展示和验收，不另建 Storybook，不再仿写第二套组件。Markdown 记录真实入口、参数、插槽与来源；组件能力和样式仍由工程实现负责。历史 `prototype-components.md` 中的订单适配仅用于旧版兼容。

### 基础组件覆盖与证据

每个页面清点实际存在的 Checkbox/Radio、Input/Select/日期、Button/Icon、Tag/Label、Table、Pagination 与弹层，逐项对应当前基线、variant/size/state、实现位置和验证状态。业务职责目录不能代替基础控件覆盖。选择框按权威系统核验范围与行为，原 input 和事件仅在正确时复用，验证单选、半选、全选、取消与焦点；Tag 核对各字段是否用 Tag 或纯文本，以及尺寸、圆角、边框、背景和文字语义。具体尺寸与样式取自目标环境组件及 Token。

用户指定当前运行环境时，先读取真实组件表现。与本地 WIP 或泛用规范冲突的项记录具体差异；不静默替换用户选定基线。业务内容一致、组件状态还原与页面组合分别给出证据。缺少基础控件验证时不得声称整页组件还原完成。

## 4. 一次修改的完整链路

1. **产品改逻辑**：记录旧行为 → 新行为、来源与受影响条目。只改某一列时，保留页面和其余列的稳定 ID。
2. **更新契约**：更新该列的含义、展示、组件与适用状态；如会影响查询、详情或导出，同步列出影响。不要因为“一列”而漏掉实际影响，也不因此重做全页面。
3. **检查组件能力**：已有 Token/atom/业务组件能够表达就复用；确有缺口再补组件或变体。修改展示不自动产生新弹窗、新状态或新权限。
4. **生成并操作原型**：按共同契约更新 LFerp，保留无关逻辑，回读默认/查询/空态/分页/详情等受影响行为，给出前后变化。
5. **同步 Figma 草稿**：在对应列、组件、状态或页面上标记条目 ID、来源和变化；关联 Markdown 位置与摘要。Figma 流程说明使用同一正文，不另写业务口径。
6. **评审与定稿**：按真实评审决定处理差异，记录最终 Markdown 摘要及页面/节点版本；未确认项单列，不把 agent 建议当定稿。
7. **交付开发**：交付同一版 Markdown、LFerp 页面、Figma 节点、变化清单和验收结果；开发映射真实 SDK，复用 Admin 组件。未生成 Admin 实现就明确仅交接。
8. **下一轮**：从这次实际定稿版本开始，重复受影响步骤。定稿、Git 合并、Figma 库发布、上线分别记录。

零售订单的首个实例与差异见 [零售订单原型契约](examples/retail-order-prototype.md)。该实例正在本地验证，不代表整套组件库、所有订单业务和 Admin 实现已经完成。

## 跨模块选型

基础组件与模板先查 [component-catalog.md](component-catalog.md)。订单只作为一个验证样本；单选、开关、上传、树选择、表单和详情不能因订单未使用而遗漏。按运行/代码/状态证据分别登记，订单特有动作阈值与 default 密度不推广为全局规则。
